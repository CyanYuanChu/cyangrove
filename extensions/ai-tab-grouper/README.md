# AI 自动标签分组（Chrome Manifest V3）

这是一个可直接加载到 Chrome 121 及以上版本的扩展。它读取当前浏览器标签的域名、标题（可选 URL 路径），按自定义 Prompt 通过 ACP 请求本机 Agent（也可手动选择 OpenAI 兼容接口），再通过 Chrome `tabs` / `tabGroups` API 创建标签组。

同时，扩展会在 YouTube 播放页提供和“哔哩哔哩(Bilibili)播放器扩展”一致的基础倍速快捷键。

## 0.7.1：ACP 与插件内桥接开关

默认通过 ACP v1 连接 **Codex**，可在设置页选择 **Pi** 或 **Claude Code**。自动分组与 AI 对话共用所选 Agent。模型 ID 留空时使用该 Agent 的默认模型；切换 Agent 会清空之前填写的模型 ID。旧版 Ollama 配置升级后默认切换到 ACP，不会自动调用 Ollama。原有 HTTP 配置保留在「OpenAI 兼容接口」中，只有主动选择此连接方式后才使用。

首次在 Cyan Grove 的「浏览器桥接」中安装适配器。然后在 Chrome 的 `chrome://extensions` 重新加载插件，弹窗中就会出现 **ACP 桥接开关**：

1. 点击「开启桥接」：通过 Chrome Native Messaging 控制 Grove，必要时在后台启动 Grove，开启服务并自动保存本机密钥，无须手动复制。
2. 关闭开关：停止桥接及当前 Agent 请求。即使 HTTP 服务已停止，下次仍可从插件直接开启。
3. 设置页可选 Codex / Pi / Claude Code，模型 ID 可留空。保存后测试连接。
4. 如果提示控制组件未就绪，先打开新版 Grove 一次，使其注册本机 Chrome 控制组件，再重新加载扩展。插件目录改变后需在 Grove 中核对扩展 ID。

需要 Node.js 22+ 和 npm。Codex 适配器自带 Codex CLI；Pi 还需本机 `pi`。在终端分别完成所需 Agent 的登录。Grove 的「连接插件」入口仍可用于手动重新配对。

桥接只监听 `127.0.0.1:48765`，拒绝非指定扩展来源及无 Bearer 密钥的模型请求。关闭开关会停止服务与当前 Agent 子进程；关闭 Grove 窗口继续运行，退出 Grove 时停止。开启状态会在 Grove 下次启动时恢复。没有另外安装开机 LaunchAgent。Native Messaging 控制器只接受 `start` / `stop` / `status`，宿主清单只允许指定 Chrome 扩展；网页不能调用它。

适配器版本锁定在 `bridge/package-lock.json`：`@agentclientprotocol/codex-acp` 2.3.0、`@agentclientprotocol/claude-agent-acp` 0.97.0、`pi-acp` 0.0.34。它们是各自项目提供的 ACP 适配器；Codex 本身通过 App Server 接入适配器。来源：[Codex App Server](https://developers.openai.com/codex/app-server)、[Codex ACP](https://github.com/agentclientprotocol/codex-acp)、[Claude ACP](https://github.com/agentclientprotocol/claude-agent-acp)、[Pi ACP](https://github.com/svkozak/pi-acp)、[ACP v1](https://agentclientprotocol.com/protocol/v1/initialization)。

每次请求创建独立 ACP 会话和临时工作目录，只收集该会话的文本消息，忽略推理与启动消息。Pi 使用关闭工具与扩展的包装启动脚本；Claude 设置空工具集；Codex 使用只读模式并关闭 shell 工具。桥接不提供文件、终端或 MCP 功能，额外权限请求会被拒绝。只有 `end_turn` 完成且 JSON 校验通过的结果才交给原有 Chrome 标签操作层。

桥接密钥与 API Key 只保存在当前设备，不写入 Chrome Sync 或 GitHub。Agent 登录凭据继续由各自 Agent 管理。适配器在本机应用数据目录安装，不打包进插件，也不提交 `node_modules`。

验证命令：

```sh
for test in tests/*.test.js; do node "$test" || exit 1; done
node --test tests/acp-*.test.mjs
```

## 0.6.1：弹窗内直接对话与 JSON 格式修复

“最近页面”和“AI 对话”现在位于同一个插件弹窗中，用顶部并列页签切换，无须打开设置页。首次使用直接进入 AI 对话，以后记住上次选择。草稿和对话记录保留；发送后由后台执行，关闭弹窗不影响任务，重新打开可查看结果。设置页的完整对话区继续保留，记录共用。

对话请求启用接口的 `response_format: {"type":"json_object"}` 约束；若返回内容仍无法解析，仅自动重试一次格式修复。校验成功前不操作标签。被截断的模型输出和连续两次格式失败会明确报错；处理失败时不会再显示“已处理”的成功提示。

模型可看到最近访问时间和插件实际记录的新建时间。插件从本次版本生效后记录标签创建事件，存于当前浏览器会话的 `chrome.storage.session`；旧标签没有创建记录时保持未知，不会伪造时间。“最近新开”与“最近访问”分别处理，缺少新建顺序时追问用户指定保留标题或改用最近访问。关闭操作支持独立的 `keepTabIds`；保留目标已关闭/变化时，停止关闭其他页面。

## 0.6.0：用文字对话管理标签

弹窗点击“AI 对话”，或在设置页侧栏选择“AI 对话”。复用已保存的接口、模型和 API Key，无须再配置一套服务。输入文字即可；可通过系统语音输入法把语音转成文字，插件不需要麦克风权限。

支持的要求示例：

- “把所有 B 站视频页面关掉。”
- “关闭「视频娱乐」分组里的全部页面，保留文档。”
- “找出所有文档页面。”
- “切换到力扣页面。”
- 先查找页面，再说“把刚才那些都关掉”。

默认操作当前对话页所在窗口，可切换到全部窗口。模型从本次快照中选择目标，输出查找、定位、关闭或需要补充信息四类结果；后台验证 ID 后执行。关闭命令会直接执行，不要求另点确认。仅说“删除分组”但未说明是否关闭页面时，助手会询问含义；本版尚未提供取消分组、移动分组和网页正文操作。

模型只接收用户消息、最近对话及标签元数据，不读取网页正文。路径是否发送继续由原有“发送 URL 路径与查询参数”设置决定。模型等待期间导航或换组的关闭目标会被跳过。模型不能执行任意脚本，也不能操作当前快照以外的 ID。单次快照遵守已有分析上限，省略页面时会在结果中说明。

对话保留最近 24 条消息在当前设备，不同步。结果展示最多 50 个页面名称，并保留完整目标 ID 供后续对话引用；清空对话不改变浏览器标签。关闭浏览器后台导致中断时会提示重新发送。真实关闭动作由 Chrome `tabs.remove` 完成，关闭后可按 Chrome 正常方式恢复最近关闭的标签。

实现文件：`src/assistant-core.js` 负责提示词、动作校验和执行；`src/background.js` 负责模型请求、会话状态与后台调度；`src/assistant.js` 和 `assistant.css` 负责文字对话界面。没有新增权限或第三方运行依赖。

## 0.5.1：点击跳转修复

页面切换由后台接收 `ACTIVATE_TAB` 后独立完成，不再依赖弹窗保持打开。后台先重新读取标签的当前窗口和组，展开组、激活标签，再聚焦目标窗口；最小化窗口会恢复，最大化窗口保持原状态。页面已关闭或窗口聚焦失败时会显示具体错误。若前台与后台版本不一致，会明确提示重新加载整个扩展。

## 0.5.0：最近页面与全新界面

弹窗和设置页都提供“最近访问”列表，默认展示最近切换到的 10 个已打开网页，可选择 20 / 50 个和全部窗口 / 当前窗口。输入标题、网址或分组名可搜索该范围内的全部已打开网页，不受最近列表数量限制；多个关键词按同时匹配处理。列表包含固定标签和已分组标签，独立于模型的分类筛选条件。

点击结果会展开原分组、聚焦所属窗口并激活原标签，不复制页面、不改变标签的分组归属。搜索框支持方向键向下进入列表、回车打开首项、Esc 清空搜索；列表内上下方向键可移动焦点。此功能不调用模型。

最近访问依据 Chrome `tabs.Tab.lastAccessed` 排序，表示标签最后一次在窗口中成为活动标签的时间，不表示新建时间。没有时间信息时显示“时间未知”。内部页面和扩展页面不显示；文件页面保留。显示数量与窗口偏好保存在本机，页面信息按需读取，不额外存储浏览时间线。

界面统一为暖白与墨绿配色，重做了图标、弹窗、分区导航、模型连接表单、分类指令编辑器、运行状态与窄屏布局。原有配置字段继续保留。升级时在 `chrome://extensions` 为原扩展点击“重新加载”，无须删除或重新安装。

## 已实现的能力

- 自定义分类 Prompt，内置中文分类模板。
- OpenAI 兼容接口：Ollama、LM Studio、vLLM、OpenAI 或其他自部署服务都可配置。
- 自动闹钟频率 1–1440 分钟；默认每 5 分钟检查一次。
- 标签指纹变化检测：没有新增、关闭、移动、导航、标题变化时，定时检查不会调用模型。
- 安全预览模式：默认自动任务只生成预览，不直接移动标签；勾选“自动应用模型结果”后才会无人值守地应用。手动点击“立即分析并分组”会直接应用本次结果。
- 依据域名和标题分类；可选发送 URL 路径和查询参数。
- 支持全部窗口；如果模型把不同窗口的标签放进同组，扩展会按窗口拆成同名组，因为 Chrome 标签组不能跨窗口。
- 只清理本扩展上次创建的标签组；不会删除用户手动创建的旧标签组。重新整理时，模型命中的标签会被移动到新的 AI 标签组中。
- 模型调用失败时不改动标签组，并在设置页显示错误。
- 固定标签、已有标签组、组折叠状态、单次最大标签数均可配置。
- YouTube 视频快捷键：直接按 `=` 每次加速 `0.25×`（最高 `5×`），`-` 每次减速 `0.25×`（最低 `0.25×`）；并显示短暂的倍速提示。

## 安装

1. 打开 `chrome://extensions`，开启右上角“开发者模式”。
2. 点击“加载已解压的扩展程序”，选择本目录：`ai-tab-grouper`。
3. 点击扩展图标进入“打开设置”。选择模型预设，确认模型名、Prompt 和自动运行频率后保存。
4. 第一次建议点击“测试模型连接”，确认无误后点击“立即分析并分组”。如果要完全自动应用，在设置中勾选“自动应用模型结果”；否则后台只生成可确认的预览。
5. 如果 Chrome 里已经加载过旧版本，打开扩展管理页点击该扩展的刷新按钮，再刷新已打开的 YouTube 页面。

## Ollama 返回 HTTP 403 或空响应

Ollama 需要允许插件的来源。macOS 桌面版可通过 `launchctl setenv OLLAMA_ORIGINS "chrome-extension://你的扩展ID"` 设置，再退出并重新启动 Ollama。扩展 ID 可在 `chrome://extensions` 的开发者模式中查看；使用后台 LaunchAgent 时，需在该服务的 `EnvironmentVariables` 中设置同一变量，再重新加载服务。具体方式见 [Ollama 官方 FAQ](https://docs.ollama.com/faq#how-can-i-allow-additional-web-origins-to-access-ollama)。

如果桌面版和独立的 `ollama serve` 同时启动，应确认实际占用 11434 端口的是哪一个：配置只对继承了环境变量的进程生效。只允许所需扩展的 ID 即可，无须开放所有来源。

0.4.4 会在一次模型请求的 180 秒超时范围内定期调用扩展 API，防止 Chrome 后台因等待模型而休眠；请求结束后立即停止保活。HTTP 错误和空响应也会分别提示，不再统一显示为“非 JSON”。

## 本地模型示例

Ollama：

- 接口：`http://127.0.0.1:11434/v1/chat/completions`
- API Key：`ollama`（本地 Ollama 通常不校验，但保留该字段）
- 模型：填你本机已安装的模型，例如 `qwen3.5:35b`

LM Studio：

- 接口：`http://127.0.0.1:1234/v1/chat/completions`
- API Key：`lm-studio`
- 模型：填 LM Studio 当前加载的模型标识

DeepSeek：

- 接口：`https://api.deepseek.com/chat/completions`
- API Key：在 DeepSeek 控制台创建并粘贴到扩展设置；不会上传到本项目
- 模型：`deepseek-v4-flash` 或 `deepseek-v4-pro`

给其他人使用时，用户只需要在“模型连接”里选择 DeepSeek、Ollama、LM Studio 或 OpenAI 预设，确认模型名称，粘贴自己的 API Key 后点击“测试模型连接”。也可以直接填写任何 OpenAI 兼容接口地址。选择 HTTP 接口时，模型请求由用户浏览器直接发送到填写的地址；选择 ACP 时经本机 Grove 桥接。

## 设计说明

```text
Chrome tabs events
        │
        ▼
计算标签指纹（id / window / index / url / title）
        │
        ├── 指纹没变：跳过模型调用
        │
        └── 指纹变化 + alarm 到期
                    │
                    ▼
            发送域名/标题/可选路径
                    │
                    ▼
              OpenAI 兼容模型
                    │ JSON groups
                    ▼
       校验 tabId → 按窗口创建 Chrome 标签组
```

指纹不包含 `groupId`，这样扩展自己创建标签组时不会因为 Chrome 的分组事件触发无意义的下一次模型调用。模型返回结果会先校验：未知标签 ID 会丢弃、重复标签只保留第一次、无有效分组则整次失败。

## 隐私与限制

默认只把域名和标题发给模型；打开“URL 路径和查询参数”后，路径也会发给你配置的接口。`chrome://`、扩展页、开发者工具页等内部页面不会送入模型。API Key 使用 Chrome 本地扩展存储，不会被上传到本项目。

这是一个本地优先的 MVP：目前同步的是非敏感设置，不同步 API Key、桥接密钥、运行状态和具体标签组；流式输出、按域名白名单和手动拖拽后的锁定规则仍暂未提供。如果模型服务暴露在局域网或公网，请自行配置鉴权和 HTTPS。

## 跨设备配置同步

扩展会把 Prompt、模型连接地址、筛选条件和自动运行设置写入 `chrome.storage.sync`，同一 Chrome 账号在其他设备安装同一个扩展后即可读取这些设置。API Key 保留在每台设备的本地存储中，需要在新设备单独填写。

`chrome.storage.sync` 不是自动安装机制：本地“加载已解压的扩展程序”不会自动出现在另一台设备。个人使用建议将扩展以未公开方式发布到 Chrome Web Store，首次在 Mac mini 安装一次；如果需要完全静默安装，则要使用 Chrome Enterprise 的扩展强制安装策略。

具体标签组不会跨设备复制，因为 `tabId` 和 `groupId` 只在当前 Chrome 实例有效。要同步分组逻辑，应保存域名、URL 匹配规则和分组名称，再由每台设备重新匹配标签。

## YouTube 倍速快捷键

打开任意 YouTube 视频后，直接按下：

- `=`：提高 `0.25×`，最高 `5×`
- `-`：降低 `0.25×`，最低 `0.25×`

快捷键只在 YouTube 页面生效；当焦点位于输入框、文本框或可编辑区域时，扩展不会拦截按键。YouTube 的单页导航切换视频后，会沿用本次通过快捷键设置的速度。
